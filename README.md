# dsh-workbench

[English](README.en.md)

DeepSeek Harness（DSH）桌面端的工作台插件，提供任务清单、改动审阅、检查点、会话整理、用量统计、页面发布、模型设置、会话标题等功能。每项功能在「插件」页中独立显示，可以分别启用或停用；停用后恢复被替换的 DSH 界面。

## 使用要求

- DeepSeek Harness 桌面端：`>=0.2.2-rc.2 <0.3.0-0`（见 `package.json` 的 `engines.dsh`，范围外版本不加载）；已在 App 0.2.2-rc.5 上验证。
- 目前只支持 macOS；Windows 还不支持。
- 从源码构建时需要 Node.js `>=22.19.0` 和 npm。安装已经生成的 tgz 不需要构建。

## 安装

目前尚未发布到 npm。到 [GitHub Releases](https://github.com/Miint-Sunny/dsh-workbench/releases) 下载 tgz，保存到本机后，在 DSH「插件」页选择「添加插件」，输入该文件的**绝对路径**，例如 `/absolute/path/miint-sunny-dsh-workbench-0.2.0.tgz`。

也可以完全退出 DSH 后，用 App 自带的 `dsh` 安装到指定 profile；以下示例使用 `desktop`：

```sh
dsh plugin --profile desktop add /absolute/path/miint-sunny-dsh-workbench-0.2.0.tgz
```

以后发布到 npm 后，在同一入口输入 `@miint-sunny/dsh-workbench`，或执行：

```sh
dsh plugin --profile desktop add @miint-sunny/dsh-workbench
```

打开 DSH 后，在「插件」页确认工作台的行已加载。每项功能可单独开关；「工作台」（`dsh-workbench`）根行负责加载功能界面，停用它会隐藏所有工作台界面。可选功能缺少依赖时，相关行或预设说明会提示原因。

## 更新和卸载

按 npm 包名安装后，在「插件」页检查并安装更新。本地 tgz 安装没有版本更新按钮：先卸载工作台，再通过「添加插件」安装新版 tgz 的绝对路径。

卸载时在「插件」页移除工作台。也可以完全退出 DSH 后执行 `dsh plugin --profile desktop remove @miint-sunny/dsh-workbench`。更换安装来源或版本前，请备份自己的 profile 和工作台数据；卸载插件不等于删除已有的页面、检查点、记忆和设置。

## 从独立插件迁移

「模型设置」和「会话标题」原来是两个独立插件（`@miint-sunny/dsh-model-settings`、`@miint-sunny/dsh-session-title-headtail`），已并入工作台 0.2.0，以后不单独发布。装过的，先在「插件」页卸载它们，再安装或升级工作台，然后重启 DSH。

- 两边同时装着时，工作台里「模型设置」「OpenCode 会话 ID」「会话标题」这几行不加载，「插件」页写明是哪个旧插件；旧插件照常工作，工作台其余的行不受影响。卸载旧插件后重启，这几行才加载。
- 提供商、模型、API 密钥和默认模型保存在 DSH 的设置和凭据中，会话标题保存在会话日志中，换装不会丢失。
- 按旧行 ID（`model-settings`、`model-settings-opencode-session`、`session-title-headtail`）写在 profile 中的设置不会跟过来；新的行 ID 是 `dsh-workbench-model-settings`、`dsh-workbench-opencode-session`、`dsh-workbench-session-title`。

## 整包与单装包

整包与七个单装包使用相同的功能行 ID，不能同时安装。发生混装时，相关功能行不加载，「插件」页和启动日志会列出冲突；移除冲突包，再重新加载 profile。七个单装包之间可以组合安装。

| 单装包 | 包含功能 |
| --- | --- |
| `@miint-sunny/dsh-workbench-usage` | 用量主页、余额与额度、上下文、闲时压缩 |
| `@miint-sunny/dsh-workbench-checkpoints` | 检查点、重新生成和编辑重发、工作树管理 |
| `@miint-sunny/dsh-workbench-review` | 审阅（改动审阅和本地审查）、计划全文、选中文字回复、提交与变更请求命令 |
| `@miint-sunny/dsh-workbench-navigation` | 会话整理、会话查找、待处理筛选、命令面板、新标签页、轮次导航、会话顶栏、浏览器视口尺寸、会话标题 |
| `@miint-sunny/dsh-workbench-pages` | 网页发布、设计画布 |
| `@miint-sunny/dsh-workbench-settings` | MCP 可见性、放行规则、工作区信任、设置页图标、工作区文件夹和权限、保护 DSH 数据和工作区、模型设置、OpenCode 会话 ID |
| `@miint-sunny/dsh-workbench-essentials` | 任务清单和收尾框、系统通知、防休眠、项目记忆、侧边对话、工具按需出现、新会话卡片 |

单装包的安装、更新和卸载方式相同，把包名换成对应名称即可。代码模式和全开模式只由整包提供。

## 功能

### 对话与导航

- **任务清单和收尾框**：显示任务进度；模型通过 `wrap_up` 给出总结和需要确认的选项，点击选项会发送相应消息。第一个选项是推荐项，输入框为空时按 ⌘↵（Windows、Linux 为 Ctrl+Enter）即可选择；关闭只收起问题和选项，不发送消息。
- **新会话卡片**：模型认为某件事适合另开会话时，通过 `propose_session` 在这一轮末尾显示卡片，包含题目、交给新会话的说明，以及工作区、工作树、Agent 预设、模型、推理等级和权限选项。默认点击「开始」才新建会话；你在这一轮亲口要求另开会话、选项又不越过当前会话（工作区相同，权限不高于当前会话）时，直接新建。要用完全权限而当前会话不是时，点击「开始」或按 ⌘↵ 会先请你确认。「在当前会话处理」会以你的名义发送一条消息，关闭则只记录不再提议。你在这一轮交代的事适合单独做时，模型也可以传 `ask: true`（只填 `title` 和 `brief`），在这一轮末尾显示一张「要另开一个会话吗？」卡片，这一轮随即结束，输入框照常可用。这种卡片一轮最多一张，没有选项和关闭：「新建会话」（⌘↵）用当前会话的设置新建，不建工作树，也不改记住的上一次模型；工作区、选项或权限不能原样沿用时不新建，卡片上写明原因。「在当前会话处理」（焦点不在输入框时按 Esc）会以你的名义发送一条消息。「不再询问」菜单里有「总是新建会话」「总是在当前会话处理」和「设置」；保存「总是……」后，之后的提议按新设置处理。「总是新建会话」不能沿用当前设置时，仍显示这张卡片。若偏好保存失败，这一次仍按你选的动作处理，之后继续使用原来的设置。要改回每次询问，在插件页工作台的「新会话卡片」一行把「模型提议另开会话时」改成「询问」。一轮最多三张（含 `ask: true`），同一件事不重复提议；从卡片开出的会话不能再提议。新会话停下（完成、等待回答、错误）时向当前会话回报一次。DSH 侧边栏不支持会话层级，新会话开在同一工作区，手动排序时排在当前会话下方。
- **审阅**：右侧栏的「审阅」标签，范围有未暂存、已暂存、未提交、分支和每一轮的改动。可以按整个范围、文件或一处暂存、取消暂存和回退（回退可以撤销，未跟踪的文件移到废纸篓），提交、推送到提交框标明的目标，在游离的 HEAD 上建分支，用单独的请求生成提交信息；行评论可在当前浏览器标签页刷新后继续编辑，一起发给模型。入口：每轮末尾的改动卡片、右侧栏新标签页、会话「更多操作」、`/review` 跑完。会话进行中可以暂存和取消暂存，回退和撤销要等会话停下。文件和看到的差异对不上时拒绝操作并重新读取。
- **重新生成和编辑重发**：从提问前分叉新会话，原会话保留。提问含附件、引用或轮次内插入消息时不可用。
- **选中文字回复与计划全文**：选中文字后回复或引用；待审计划直接显示在对话中，发送回复可要求修改。
- **检查点**：在顶层轮次开始时保存工作区状态，可以恢复文件、分叉会话或同时执行，恢复后可撤销。
- **会话查找与轮次导航**：⌘F 查找已显示的文字；轮次刻度支持预览、拖动跳转和书签。书签只保存在当前浏览器。
- **侧边对话与会话整理**：在右侧栏打开另一会话，按颜色标签整理会话，标为未读；「需要你处理」筛选汇总审批、问题和待审计划。
- **命令面板**：搜索会话、操作、入口和命令；以 `/` 开头只查命令。请先在「设置 → 快捷键」移除「搜索会话」的 ⌘K，再把 ⌘K 分配给「命令面板」。
- **新标签页与会话顶栏**：右侧栏入口可置顶和排序；会话顶栏将「更多操作」移到左侧，将普通变更请求入口放入该菜单，需要处理时仍显示顶栏提示。
- **会话标题**：新会话发出第一条消息后由模型起名，只看这一条；侧栏会话菜单的「重新起名」或 `/retitle` 参考首条和最近的对话重算，会替换手动改过的标题。自动起名失败、标题还是临时标题的会话，在之后一轮结束时补起一次。这一行开着时顶替 DSH 自带的首条消息生成标题（标题服务同时只接受一个提供方）；停用这一行后，DSH 自带的首条消息生成标题随即回来，不用重启。
- **浏览器视口尺寸**：右侧栏浏览器的工具栏增加「视口尺寸」按钮，可选手机、平板、桌面或自定义尺寸（240 到 3840 像素），并可横竖对调。网页按该尺寸排版，再缩放进卡片，工具栏下方显示尺寸和缩放比例；每张卡片各自记住，新开的卡片为自动。只改页面排版的宽高，不模拟触摸、设备像素比和浏览器标识。

### 用量与上下文

- **用量主页**：统计会话日志中的 Token、模型请求和估算费用，提供时间范围、趋势及分项明细。打开或刷新时读取，不后台轮询。
- **余额与额度**：查询已经配置凭据的 DeepSeek、OpenCode Go 和 GLM Coding Plan。凭据只在宿主进程中使用。
- **上下文**：查看请求中的工具、技能、记忆和工具结果，以及最近请求和压缩记录；查看页面不调用模型。
- **闲时压缩**：按会话设置工作时或空闲时的压缩阈值，默认关闭。只对配置名单中的预设生效。

### 代码与页面

- **网页发布与设计画布**：`publish_page` 将 HTML 及其本地资源保存为带版本的页面；设计画布提供桌面和手机画板、元素评论、CSS 变量预览及 HTML 导出。
- **本地审查**：`/review uncommitted` 或 `/review --base <本地分支>` 启动独立的只读审查，发现显示在「审阅」的差异行下面；未跟踪文件需显式选入，敏感文件、符号链接、二进制和过大文件不审查。
- **提交与变更请求命令**：`/commit`、`/push`、`/pr`、`/fix-ci` 发送相应任务给模型，正常的权限审批仍然有效。
- **工作树管理**：在会话菜单创建、进入和清理 Git 工作树。清理移入废纸篓并保留分支；存在未发布提交或仍被会话使用时拒绝清理。
- **项目记忆**：`memory_view` 和 `memory_write` 保存同一项目的事实，Git 工作树共享记忆；子智能体不提供这两个工具。

### 设置与系统

- **MCP 可见性**：按会话或项目隐藏服务器及工具，并查看本次启动后的调用数；不修改服务器配置。
- **放行规则**：为简单 bash 命令保存经过确认的项目、目录、可执行文件和参数规则；管道、重定向和展开不适用，DSH 自动审查仍然执行。
- **工作区信任**：为支持的 HTML 预览控制是否读取工作区本地资源；默认使用静态预览。信任记录可在设置中撤销。
- **系统通知与防休眠**：后台会话完成或等待操作时发送通知；工作期间保持 Mac 唤醒，默认只在接通电源时启用。
- **切换 Agent 预设**。会话开始以后，可在会话顶栏的 Agent 预设标签上切换标准模式、代码模式与全开模式。切换前先确认：显示工具增减、系统提示词变化和下一次请求预计未命中的 token 数，可先执行 `/compact`。只有空闲且没有待答问题、审批、计划审阅或排队输入的根会话才可切换。切换后下一次请求就用新预设，重启、重放和分叉以后也是新预设。空白会话照旧用顶栏的官方选择器。
- **工具按需出现**：代码模式先加载常用工具，其余工具由模型检索后选入。小功能单装包默认停用此行。
- **设置页图标**：为养鱼（dsh-bili-whale）和订阅（dsh-plugin-subscriptions）的设置页补上图标，换掉默认的齿轮；这两个插件自己提供图标时，使用它们的。
- **工作区文件夹和权限**：在侧边栏工作区的右键菜单打开「工作区设置…」，可以改名、添加子文件夹和外部文件夹。子文件夹单独成为工作区，该工作区的会话默认不能写主文件夹，可设为可写；外部文件夹在「工作区内修改」权限下和主文件夹一样可写。主文件夹那一行的「更换文件夹…」把工作区迁移到新文件夹，或并入那里已有的工作区：会话、分叉会话、子智能体会话和工作台的检查点、项目记忆、工作区信任设置一起迁移。迁移需要退出 DSH，完成后自动重新打开；迁移前自动备份，可在重新打开后的提示或工作区设置里撤销。
- **模型设置**：替换「设置 → 模型」页。打开就是两栏，左边分类、右边提供商；已添加的点开进详情页，没添加的点开进填写页。详情页可以替换和清除 API 密钥、整理模型目录、检查连接；「获取可用模型」只在点击时向提供商请求一次。OpenCode、OpenRouter 这类混用几种 API 协议的提供商，目录外的模型也能添加，按协议存成附属条目。提供商、模型和 API 密钥仍保存在 DSH 的设置和凭据中；停用这一行后恢复 DSH 自带的模型页。给这些目录外的 OpenCode 模型补会话 ID 请求头的是单独一行「OpenCode 会话 ID」，只停用模型设置时可以保留它。
- **保护 DSH 数据和工作区**：智能体在所有会话和子智能体中尝试写入、移动或删除 `$DSH_HOME/storages` 与 `$DSH_HOME/sessions`，或移动、改名、删除已登记工作区的根文件夹本身时，先触发人工审批（并说明正确做法）；能识别的只读命令放行。命令过长、嵌套过深或无法确认写入目标时也会询问。放行规则不代答，自动审查不能放行。

## 设置

在「插件」页对应行的「配置」中调整设置；部分功能也提供独立设置页。下表列出主要默认值。`$DSH_HOME` 表示 DSH 数据目录。

| 功能 | 默认值或配置位置 |
| --- | --- |
| 改动审阅 | 回退备份保留 `keepDays: 30` 天 |
| 检查点 | 保留 14 天；每会话 2048 MB；非 Git 文件上限 2 MB；首次工具执行前最多等待 5 秒 |
| 重新生成 | 分叉后归档原会话默认关闭 |
| 系统通知 | 四种事件默认开启；前台通知、显示回复首句默认关闭；可排除预设 |
| 防休眠 | `graceMs: 60000`；`alsoOnBattery: false` |
| 项目记忆 | `maxBytes: 16384` |
| 用量与额度 | `$DSH_HOME/dsh-workbench/usage.json` 和 `quota.json`；额度缓存 300 秒，查询超时 10 秒 |
| 闲时压缩 | 默认关闭；按会话设置，默认值和提示词位于「设置 → 压缩」 |
| 本地审查 | 默认使用主会话模型，可通过行配置 `model` 指定 |
| 提交与变更请求命令 | `locale: zh`，可改为 `en` |
| 代码模式与全开模式 | 名称跟随界面语言，可通过 `locale` 固定；LSP 和 MCP 均为可选 |
| 工作区文件夹和权限 | `$DSH_HOME/dsh-workbench/workspace-folders.json`，按工作区记录外部文件夹和子文件夹的「可写」；迁移记录和备份在 `$DSH_HOME/dsh-workbench/workspace-moves/`，行配置 `moveUndoDays` 是迁移完成后多少天内提供撤销（默认 30） |
| 模型设置 | 没有自己的存档：提供商、模型和默认模型在 DSH 的设置中，API 密钥在 DSH 的凭据中；「检查连接」一次最多输出 16 个 token，20 秒超时 |
| 会话标题 | `tailMessages: 6`、`refreshEveryPrompts: 0`（轮末不自动重算），其余见 [预设配置](docs/configuration.md) 的「会话标题」 |
| 新会话卡片 | 默认 `ownSession: "ask"`（可选 `ask`、`always-new`、`always-here`），保存于 `$DSH_HOME/dsh-workbench/session-cards-prefs.json`，经 `GET/POST /api/dsh-workbench.session-cards.prefs` 读写；状态存档于 `$DSH_HOME/dsh-workbench/session-cards.json` |

整包的 `dsh-workbench-preset-switch` 行可配置 `presets`（上述三个模式的子集，按配置顺序显示）和 `compactFirstAboveTokens`（默认为 65536）。达到阈值时默认勾选先压缩。估算依赖当前模型、上下文与工具定义，无法确定的项目在预览中标为未知。

LSP 路径、MCP JSON 格式与配置示例见 [预设配置](docs/configuration.md)。

## 已知限制

- 已开始的会话切换预设时，用的是 DSH 的 `recompose` 接口，官方注明它只给空白会话用（官方选择器对已开始的会话会拒绝）。以后的 DSH 版本可能收紧这个接口；那时切换会回「预设不可用」，会话保持原预设。
- 子智能体保持创建时的预设，切换只作用于当前会话。
- DeepSeek V4 Flash 这类在对话中追加系统提示词的模型，来回切换会在上下文里留下几份系统提示词，直到压缩上下文。先压缩是独立操作，即使后续切换失败，压缩也已生效。

- 仅支持 macOS。Windows 还不支持。
- 检查点在 Git 仓库中包含未跟踪文件，不包含被忽略文件；非 Git 目录只记录文件工具改动，不记录命令行改动。仅大小写不同的重命名可能无法恢复。
- 每一轮的改动依赖当前宿主进程的记录；重启后旧轮次可能无法查看，已保存的回退撤销记录仍保留。审阅面板里 Git 范围的撤销只在当前窗口里可用，刷新页面后不能再撤销。
- 会话查找只搜索已显示的文字；跨越多个文本节点的词可能无法匹配。轮次导航依赖 DSH 页面结构，不匹配时相关行配置会显示未生效。
- 发布页面在沙箱中展示，默认关闭脚本。预览会拦截 fetch、表单提交和外部图片。资源策略允许从 cdnjs、jsDelivr、unpkg 加载脚本和样式，从 Google Fonts 加载样式和字体。在预览或设计面板点「运行脚本」后，当前版本即可运行脚本。浏览器会记住这次选择，存储不可用时只在这次打开期间生效。脚本运行后，页面可以跳转到其他网站并带走页面内容。每个内联资源最多 4 MiB，每版资源合计最多 16 MiB、64 个。删除的页面保留 30 天。
- 设计画布依赖网页发布，「需要你处理」依赖会话整理，余额与额度显示依赖用量主页。
- 工作区信任需要带工作台预览补丁 v3 的 dsh-better-sidebar 0.32.0。普通安装该依赖不保证此功能可用。信任后的页面脚本可以读取获准的本地资源，也可能向外发送其内容；不要信任不熟悉的项目。预览框自身导航到 `dsh-app:` 的隔离范围尚未得到完整验证。
- 用量费用为估算值，缓存寿命来自本机样本，不代表提供方的保证。余额和额度查询需要联网，服务不可用时会显示查询失败或缓存结果。
- 工作区文件夹和权限只管写入，DSH 不限制读取。设为只读或移除文件夹之前已经启动的后台作业，在退出前仍能写入原来的文件夹；子文件夹里事先存在的、指向主文件夹文件的硬链接，可以用命令行改到主文件夹中的那个文件。工作区设置保存改动要带一个令牌，令牌只在读取文件夹列表时交给页面，挡的是别的网页和预览框；能在本机执行命令的程序（包括「工作区内修改」权限下模型运行的命令）可以直接调用 DSH 的本机接口，令牌挡不住，DSH 官方的接口也是这样。
- 更换文件夹需要退出 DSH。桌面版由工作台请 DSH 退出（AppleScript，macOS 可能询问「自动化」权限；不允许时按 ⌘Q 退出即可）；终端里运行的 DSH 需要手动退出，完成后手动重新启动。会话记录中的旧路径不会更新。撤销时，迁移后会话里新写的内容一起回到原位置；迁移后会话记录被改写、会话目录里多了别的文件、工作区登记或工作台数据有改动时不能撤销。
- 模型设置的「自定义设置」可修改显示名称（仅自定义提供商）、API 地址、API 协议（仅自定义提供商）和重试策略；Provider ID 和凭据名只读，其余字段要直接编辑 profile 的 `cordis.patch.yml`。
- 模型设置里账号型的线路只显示状态；登录只有 DeepSeek 账号在模型页上有入口，退出登录在设置左栏的账号菜单里。
- 火山方舟的 Coding Plan、Agent Plan 额度按方舟的规定只在 AI 编程工具里生效，在别处使用可能被判为滥用。
- 目录外的模型的协议按模型 ID 推断，推断不对时要在展开处手动改；地址只能在「自定义设置」里写的 API 地址和安装包目录的地址之间选。模型设置只认自己建的附属条目（显示名是「<提供商>（<协议名>）」的格式），在配置文件里改掉显示名的，按一家自定义的提供商显示。
- 删除一家提供商时，如果默认模型在它下面，DSH 的默认模型不会自动更换（和 DSH 自带的模型页一样）。
- 「会话标题」开着时，「插件」页里 DSH 自带的「首条消息生成标题」显示为等待服务（它等工作台交还许可），不是停用。开关这一行的那一刻（几毫秒）发出首条消息的新会话，可能只得到截取首条消息的临时标题；开着「会话标题」时，之后一轮结束会补起一次。
- 保护 DSH 数据和工作区拦不住的情况：外部脚本文件里的写入或删除（如 `python3 script.py` 内部调 `open(path, 'w')`）、通过变量动态拼接或混淆出的路径、已编译二进制程序、PTC `run_code` 内不经 DSH 工具而直接调 Node `fs` 的代码、持久终端（`terminal_send`）在先前已 `cd` 或分两次发命令导致单次调用看不出完整目录或命令、事先指向 `storages/` 或 `sessions/` 内部的硬链接，以及启用本行之前就已经启动的后台进程。此外，在「完全权限」（`approval: 'never'`）和所有子智能体下，插件仍能阻止这类调用执行并给出原因和提示，但因 DSH 的 `ApprovalService` 在 `never` 策略下不派发交互审批，此时无法弹出确认卡片。

## 问题反馈

在 [GitHub Issues](https://github.com/Miint-Sunny/dsh-workbench/issues) 报告问题。熟人试用时，也可以直接联系提供插件的人。

请提供 DSH App 版本、插件包名和版本、macOS 版本及芯片、操作步骤、实际结果、预期结果，以及「插件」页中未加载的行和完整报错；可以附截图。不要提交密钥、令牌、配置中的凭据或私人聊天。

## 开发

从 git 克隆以后先装开发依赖，再跑测试：

```sh
npm ci --legacy-peer-deps
npm test
```

`--legacy-peer-deps` 不能省：DSH 的 peer 依赖由 App 提供，不从 npm 装。开发依赖只有 [dsh-ui-guard](https://github.com/Miint-Sunny/dsh-ui-guard)：`npm test` 用它对照本机的 DSH App 查界面的图标和用语，没装 App 时这一条跳过。
